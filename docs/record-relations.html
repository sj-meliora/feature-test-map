제약과 규칙

  • 검증 대상자식 항목이 없는 말단 기능만 검증 대상이며, 인스턴스 시나리오는 말단 기능에만 둔다.
  • TC의 ID일련번호다. 목록을 다시 추출할 때 suite와 TC 이름이 같은 TC는 기존 번호를 유지한다.
  • 기능과 TC둘을 직접 잇는 테이블은 없다. 인스턴스 시나리오를 거쳐 구하며, 기능별 TC 개수는 뷰로 정의한다.
  • 시나리오 추가새 인스턴스 시나리오에 해당하는 TC는 기존 시나리오와의 연결을 새 시나리오로 옮긴다.
  • 원본YAML과 JSONL 파일이 원본이며, 조회용 SQLite 데이터베이스는 원본에서 생성한다.

항목 이름은 DESIGN.md의 표기를 따른다. 자료형은 SQLite를 기준으로 한 제안이며 확정된 내용이 아니다. 뷰의 이름과 항목도 제안이다. 기준: DESIGN.md의 DP-1부터 DP-5까지와 DP-7.
