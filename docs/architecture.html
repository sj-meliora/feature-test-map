제안 (미채택)

번호제안얻는 것잃는 것
제안 1원본에는 부모 ID만 적고, 계층 경로는 읽을 때 계산한다.경로와 부모 ID가 서로 어긋날 수 없다.YAML 파일을 직접 열어서는 경로를 볼 수 없다.
제안 2LLM은 기능 목록을 YAML이 아니라 조회 명령의 출력으로 읽는다.출력에 경로가 포함된다. 원본의 형식을 바꾸어도 스킬은 영향을 받지 않는다.목록을 출력하는 명령을 구현해야 한다.
제안 3기능과 인스턴스 시나리오는 YAML을 직접 편집하고, 검증 명령으로 확인한다.구현할 것이 검증 하나다. 변경 내용을 git에서 줄 단위로 검토한다.형식이 쓰는 시점에 보장되지 않으며, 검증 명령을 실행해야 오류가 드러난다.
제안 4조회할 때마다 원본을 메모리 안의 SQLite로 읽어 들인다.오래된 데이터베이스로 조회할 일이 없다. 조회 명령이 아무 파일도 쓰지 않는다.조회마다 원본을 다시 읽는다. 다른 도구가 열어 볼 데이터베이스 파일이 남지 않는다.

미결

  • ID 부여 시점추출 에이전트가 ID 칸을 비워 두는지, 제안값을 넣고 사용자가 확정하는지 정하지 않았다.
  • IMS 원본 위치IMS에서 항목 하나를 가리키는 값의 형태를 정하지 않았다. 다시 추출할 때 기존 레코드와 대조하는 기준이 된다.
  • TC와 관계TC를 추출하는 방법(FR-2)과 관계를 식별하는 주체와 판정 기준(FR-3)을 정하지 않았다.
  • 공통 모듈의 위치Module View의 variation point다. 스킬 패키지 안에 두는 변형과 별도 패키지로 두는 변형 중에서 정하지 않았다.
  • 시각화대상과 형태(FR-4)를 정하지 않았다. 데이터베이스 파일이 필요한지는 그때 판단한다.

실선 테두리는 DESIGN.md에서 결정된 내용이다. 주황색 점선 테두리와 번호는 논의 중인 제안이며 확정된 내용이 아니다. 두 뷰는 같은 구조를 실행 시점과 코드 단위의 두 관점에서 나타낸다. 구성 요소의 이름은 설명을 위한 것이며, 파일 이름과 명령 이름은 정하지 않았다. 기준: DESIGN.md의 DP-1부터 DP-7까지.
